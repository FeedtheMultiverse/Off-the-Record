Off the Record Investigation Module Skill
1. Prime Directive
Write playable situations, not novels.
The module is an interface between the GM and a living situation. Its job is not merely to describe what exists. It must expose what the GM can use while players are talking, improvising, splitting up, skipping material, solving things early, or doing something the author did not predict.
Always ask:
What is happening here, what can the investigators change, and what changes without them?

A runnable module exposes three things everywhere they matter:
- State: what is true now.
- Affordance: what investigators can inspect, test, ask, alter, exploit, prevent, reveal, or ignore.
- Transition: what changes because of action, delay, discovery, escalation, or outside forces.
If prose contains useful lore but the GM must mentally compile it into wants, clues, routes, timelines, reactions, or consequences, the module is unfinished.
The GM should be able to answer quickly:
- What is happening now?
- Who wants what?
- What can investigators interact with?
- What clues are available here?
- Where can those clues lead?
- What are NPCs doing if ignored?
- What happens if the investigators do nothing?
- What changes because of what they just did?
More prose does not repair missing machinery.
2. Off the Record Identity
Off the Record is modern paranormal investigation through the visual and narrative language of an alternate-universe 1970s newsroom, local archive, research desk, or civic bureaucracy.
Favor:
- real or plausibly real places
- municipal infrastructure, public architecture, service spaces, records, maps, signage, media, archives, malls, stations, parks, offices, motels, basements, corridors
- ordinary institutions colliding with impossible facts
- witnesses with partial views
- records that almost agree
- documents whose authors do not realize they recorded the paranormal
- dry institutional absurdity beside real human stakes
- documentary unease, local specificity, curiosity, warmth, and mounting pressure
- mysteries that begin as discrepancies and become situations
The paranormal should usually enter through a crack in the ordinary, not arrive already labeled.
Avoid generic creepypasta, lore-for-lore's-sake, vague cosmic mystery without usable rules, relentless grimness, blockbuster banter, and "haunted brochure" location tours.
When using real places, distinguish verified reality from invented alternate-universe material. Never turn real deaths, disasters, crimes, or trauma into casual supernatural decoration.
3. Canon and Minimum Invention
When revising existing material, read before inventing.
Maintain a working ledger:
- Established: explicit approved canon.
- Inferred: logical implication, not yet explicit.
- Proposed: new material introduced to solve a design need.
- Open: unresolved question.
Never silently promote Proposed to Established.
Before adding a node, NPC, faction, document, rule, monster, cosmology, or subplot:
1. identify the missing function
2. inventory existing elements
3. ask whether one can perform that function
4. connect existing material first
5. add the smallest new piece only if necessary
Prefer connective tissue over expansion.
If eleven interesting locations lack momentum, do not add location twelve. Add cross-links, movement, deadlines, clue echoes, changing access, institutional response, or a phenomenon that reacts.
When sources conflict, flag the contradiction. Keep it only if the contradiction creates intentional play; otherwise preserve the most authoritative approved source.
4. Scenario Engine
Before full prose, define six sentences:
1. Report: what ordinary thing is wrong?
2. Truth: what is actually happening?
3. Web: which people and places hold pieces of it?
4. Rule: how does the anomaly behave?
5. Pressure: what worsens if nobody intervenes?
6. Choice: what difficult decision remains once players understand enough?
If any sentence is mushy, solve that before expanding.
A strong scenario contains:
- a disturbance that naturally produces questions
- a plain GM-facing hidden situation
- human motives that remain important after the paranormal is understood
- evidence available through multiple routes
- locations where evidence, people, and pressure intersect
- anomaly rules sufficient to adjudicate experimentation
- forces that act independently
- thresholds that change the situation
- several plausible classes of intervention
- consequences that preserve player choices
The GM may remain uncertain about metaphysics, but not about the practical rules needed to run play.
5. Human Web
NPCs are moving parts, not quest dispensers or exposition machines.
Every significant NPC should be load-bearing by providing at least one function: evidence, access, pressure, authority, consequence, expertise, leverage, moral complication, or opposition.
For each major NPC define only what play needs:
Public role | Function | Want | Pressure/Fear | Knows | Believes | Hides | Volunteers | Requires leverage | Current action | If ignored | Breaking point | Movement | Relationships | Voice
Separate knowledge from belief.
At least some NPCs should act without the investigators: call someone, move, remove evidence, seek help, become unavailable, make a bad decision for understandable reasons, change tactics, or trigger institutions.
Prefer contradictions over archetypes: helpful but reputation-conscious; skeptical but observant; dishonest about one mundane fact while truthful about the impossible; warm but institutionally protective.
For conversation, use response logic rather than dialogue trees. Answer player intent if the NPC reasonably understands it. Sample lines establish voice; do not script whole conversations unless requested.
A useful response matrix:
Topic / approach	Default	Trusted	Pressured	Shown evidence	Hidden


6. Revelation Lattice
Mystery structure is a set of revelations, not a list of clues.
For each important conclusion, provide 2–3 plausible clue sources. No single failed roll, missed room, destroyed object, or absent NPC should stall the scenario.
For each revelation record:
Revelation | Clue sources | Natural homes | Fallback/echo | What players can infer
Clues should let players think. They should not merely tell the answer.
Good clues may be:
- physical
- documentary
- testimonial
- behavioral
- spatial
- temporal
- technical
- anomalous
- contradictory
Natural Home, Elastic Recovery
Evidence belongs somewhere specific enough that architecture and institutions matter. If a required clue is bypassed, recover it through another plausible source rather than teleporting it arbitrarily into the next room.
Clue redundancy does not mean duplication. Different sources should reveal different facets or degrees of certainty.
Players are allowed to solve the mystery early. Do not protect the twist. Understanding should change the problem from "what is happening?" to "what are we willing to do about it?"
7. Nodes as Interfaces
A node is any location, person, archive, event, system, or situation investigators can meaningfully engage.
Every node must justify its page space through evidence, action, pressure, character, access, or meaningful atmosphere.
Use this compact run sheet:
NODE: [Name]
- Immediate read: 1–3 sentences; visual anchor + sensory/material detail + actionable oddity.
- State: what is happening now.
- Why come here: leads that point here.
- Actionable features: things investigators can manipulate, compare, search, test, question, enter, repair, steal, document, expose, etc.
- Clues: evidence and what it supports.
- People: who is present or reachable; what they are doing.
- Pressure/Risk: active danger, cost, or constraint.
- Leads out: where evidence or access points next.
- If revisited: what changes.
- If ignored: what happens without PC intervention.
- GM truth: hidden operational facts not already centralized elsewhere.
Do not repeat centralized truths in every node. Use cross-reference language when repetition would waste context.
A node is weak if it contains atmosphere but no useful interaction, or if removing it changes nothing.
8. Maps and Flow
Point-crawls model access, information, movement, and consequence, not mandated scene order.
Diagrams may use:
[LOC] [NPC] [DOC] [CLUE] [EVENT] [THRESHOLD] [STATE] [OUTCOME]
A useful map answers:
- Where can investigators go?
- What reveals what?
- Which routes are independent?
- How can missed information be recovered?
- What moves?
- What becomes unavailable?
- Which state changes unlock, alter, or close routes?
Branches may reconverge, but consequences must not disappear when they do.
9. Pressure and Escalation
A scenario moves because clocks, institutions, people, and anomalies continue operating.
Use state-triggered beats, not scripted acts.
Possible triggers:
- elapsed time
- number of revelations found
- a threshold crossed
- an NPC contacted
- a document published
- a specific experiment
- investigators leaving or returning
- repeated entry
- damage or repair
- media, police, civic, corporate, or public attention
Each major escalation must change at least one:
- information
- access
- NPC behavior
- geography
- safety
- public awareness
- interpretation of prior evidence
- available interventions
If only the prose becomes scarier, nothing escalated.
Pressure clocks need observable signs.
A deadline with a face is often stronger than an abstract timer: an ordinary competent person arrives to perform the next institutional step. They are understandable, hard to ignore, and negotiable only through believable leverage.
Nonverbal Anomalies
Do not assume paranormal phenomena speak or think like humans.
They may communicate through temperature, sound, growth, reflections, routes, pressure, timing, electrical behavior, smell, wear, water, architecture, or memory-like sensations.
Observation and experimentation should yield true sensory evidence, not lore speeches.
10. Agency: Costs, Not Menus
Never script what investigators choose, conclude, feel, or try.
Present circumstances and responses.
For major obstacles, be prepared for several classes of approach: social, bureaucratic, investigative, technical, stealth, force, observation, supernatural experimentation, outside help, publicity, negotiation, repair, sabotage.
Unexpected plausible plans should usually receive a cost, not a veto.
Possible costs include:
- time
- money
- safety
- access
- reputation
- evidence
- privacy
- legality
- relationships
- public attention
- harm displaced onto someone else
- creating a new problem
Some things are impossible. Most merely send invoices.
Track consequences such as trust, exposure, damage, evidence held, routes lost, public knowledge, institutional reaction, and what the anomaly has learned or changed.
PC Stakes
For scenario-created investigators, give each a reason to care, something to preserve/prove/recover/protect/expose/understand, and a cost they resist paying.
Strong stakes pull sideways. No PC owns the "correct" interpretation, and different reasonable priorities complicate the final decision.
Do not overwrite campaign-character motives with bespoke one-shot stakes.
11. Documentary Worldbuilding
Handouts should reveal the world through limited institutional perspectives, not omniscient exposition.
For any important artifact define:
- Position: where the author sits relative to events/power.
- Need: what they need to believe, accomplish, protect, or justify.
- Lens: the professional/cultural framework through which they describe events.
- Blindness: what they cannot recognize, admit, measure, or say.
Good artifacts often contain accidental truth: a detail mundane to the writer but crucial to investigators.
Suitable forms include maintenance logs, newspapers, memos, maps, invoices, meeting minutes, forms, transcripts, photographs, schedules, reports, advertisements, signage, receipts, directories, archive cards, and correspondence.
Documents should have a job: clue, characterization, institutional texture, fair misdirection, escalation, leverage, or interaction. If it is merely decorative, cut it or move it to optional ephemera.
Keep player-facing and GM-facing material separate.
Player-facing: observable facts, public history, rumors, obtainable documents, witness claims, in-world maps/photos.
GM-facing: hidden motives, actual relationships, rules, triggers, timelines, consequences, contingencies, off-screen actions.
Do not duplicate both layers unless table usability requires it.
12. Resolution
Design end states, not one correct ending.
Possible interventions include contain, stop, redirect, expose, conceal, rescue, bargain, repair, destroy, relocate, preserve part rather than whole, reduce immediate harm, exploit, withdraw, or hand the problem to an institution.
For likely outcomes answer:
- What physically changes?
- Who gains or loses?
- What evidence remains?
- What becomes public?
- What official story emerges?
- What cost has an owner?
- What thread can return later?
Do not punish an answer merely because it is not the author's preferred one.
For one-shots, a player-authored epilogue may ask each player for one future image or fact after the GM establishes consequences.
13. Table-Ready Writing
A module is used while people interrupt each other.
Lead with actionable information. Put lore after the GM knows what to do with it.
Prefer:
The west service door opens onto the wrong corridor after 10:15 p.m.

over:
The western reaches conceal an unsettling impossibility.

Use:
- short operational sections
- concrete headers
- bullets for actionables and clues
- tables for clocks, evidence, schedules, and NPC movement
- concise read-aloud
- references instead of redundant repetition
- a one-page GM reference for full modules
Immediate description should usually be 1–3 sentences and include one anchor, one sensory/material detail, and one actionable oddity.
Recommended Module Order
Use only sections the scenario needs:
1. Title / headline / initial report
2. What investigators know
3. GM summary / truth
4. Anomaly rules
5. Investigator stakes
6. Cast at a glance
7. Revelation lattice
8. Map / node graph
9. Pressure clock
10. Nodes
11. Mobile events
12. NPC files
13. Documents / handouts
14. Likely interventions / resolution states
15. Aftermath / continuing threads
16. GM one-page reference
Completeness is not runnability. A shorter module that exposes its state and actionables beats a longer manuscript whose useful information must be excavated.
14. Construction Workflow
When creating or substantially revising a module:
1. Inventory canon. Established / Inferred / Proposed / Open.
2. Write the six-sentence engine.
3. Build the revelation lattice. 4–8 core revelations; 2–3 routes each.
4. Build the node graph. Remove nodes with no job.
5. Build the human web. Wants, knowledge, actions, movement, breaking points.
6. Build escalation. 3–6 states tied to time, discoveries, actions, institutions, or anomaly response.
7. Stress-test agency.
8. Create documents and optional texture.
9. Draft for table scan speed.
10. Audit and compress.
Stress-test at least:
- players miss an intended NPC
- break in
- call authorities
- go public
- leave and return
- solve the phenomenon early
- form the wrong theory
- split up
- destroy evidence
- refuse the expected hook
- invent a solution not listed in the manuscript
Respond with consequences, not prohibitions.
15. Compact Quality Gate
Before calling a module structurally complete, verify:
Engine
- Hook gives a reason to investigate.
- GM truth is plain.
- Anomaly has usable rules.
- Human motives matter.
- If PCs do nothing, events continue.
Investigation
- At least two starting leads.
- Core revelations have multiple clue routes.
- No single roll/NPC/object gates progress.
- Nodes connect and point outward.
- At least one event can come to the PCs.
- Revisited/ignored nodes can change.
Pressure
- Escalation has visible signs.
- Each stage changes state, not just mood.
- NPCs/institutions act independently.
- The climax emerges from accumulated state, not author fiat.
Agency
- Clever early solutions are allowed.
- Unexpected plans receive costs before vetoes.
- Meaningful consequences survive reconvergence.
- Resolution is not a dialogue menu.
NPCs
- Major NPCs want something now.
- Know/believe/hide are distinct where relevant.
- Each significant NPC has a function.
- Voices and reactions are differentiable.
Documents
- Important artifacts have a perspective and blind spot.
- They reveal rather than summarize omniscient truth.
- Fictional divergence is distinguishable from real-world claims.
Interface
- Actionables appear before flavor.
- Nodes are scannable.
- Player/GM information is separated.
- Repetition is centralized or removed.
- The GM can run the scenario without reverse-engineering prose.
Off the Record
- Mundane institutions matter.
- Local place/infrastructure matters.
- At least one record is meaningfully wrong.
- Human stakes remain after the strange becomes clear.
- The module feels investigated, not toured.
16. Anti-Patterns
- Haunted Brochure: cool places with no causal or investigative links. Add lattice, movement, shared rules, escalation.
- Lore Avalanche: history before present action. State current situation first.
- One-Clue Lock: one indispensable clue. Add independent routes.
- Exposition NPC: one person explains everything. Distribute knowledge.
- Fake Branch: choices reconverge and erase consequence. Preserve state differences.
- Scripted Investigator: prose dictates PC thoughts/actions. Describe evidence and reactions only.
- Mystery Box: weirdness without an underlying runnable model. Write GM truth/rules.
- Omniscient Handout: document conveniently knows everything. Give it position, need, lens, blindness.
- Atmosphere Instead of Action: eerie details cannot be tested or used. Add affordances.
- Expansion Reflex: structural weakness answered with more content. Connect before adding.
- GM Fog Machine: GM-facing prose withholds essential truth. Be explicit.
- Real-Tragedy Decoration: actual harm used as flavor. Research and create respectful fictional distance.
17. Revision Modes
When revising, diagnose first and make the smallest repair.
- /otr-structure — engine, connectivity, clue redundancy, escalation, resolutions.
- /otr-interface — convert prose into state / affordance / transition; expose actionables; create run sheets and quick references.
- /otr-glue — connect good isolated material using cross-clues, mobile NPCs/events, shared rules, escalation, revisit states; avoid new nodes.
- /otr-clues — revelation lattice, sources, fallbacks, inferences.
- /otr-npcs — wants, knowledge, belief, secrets, current action, ignored action, leverage, movement, breaking points, voice.
- /otr-docs — player-facing artifacts using Position / Need / Lens / Blindness.
- /otr-pressure — time, reactive escalation, institutions, anomaly adaptation, visible state changes.
- /otr-table-ready — compress for GM scan speed without changing canon.
- /otr-audit — report only PASS / WEAK / MISSING / CONTRADICTORY and smallest repair.
18. Agent Rules
Do:
- preserve approved names, places, clues, themes, and user intent
- solve structural problems structurally
- state GM truth plainly
- distinguish fact, belief, rumor, and proposal
- distribute clues across routes
- make situations move without PCs
- let clever investigations work
- let consequences persist
- mark substantial new canon as Proposed
- write handouts from limited perspectives
- optimize for actual table use
Do not:
- replace the user's premise with a "better" one
- add content merely to demonstrate creativity
- invent lore that has no job in play
- require one clue, NPC, question, or roll
- turn agency into menus
- call a fixed scene sequence "branching"
- bury operational facts in lyrical prose
- make every anomaly hostile, sentient, or combat-centered
- invalidate a plausible solution to protect a planned reveal
- repeat the same instruction, truth, or content in multiple sections without a usability reason
Final Principle
The investigators should feel that they arrived somewhere already in motion, pulled on a loose thread, and changed what happened next.
Build the wrong shape.
Then expose the handles.
